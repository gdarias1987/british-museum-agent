La respuesta corta

Resumen ejecutivo

El proyecto es un asistente en español con recuperación semántica, reranking, generación con Gemini y operaciones protegidas por MCP. La arquitectura es real, modular y fue verificada localmente; el cumplimiento global del enunciado sigue siendo parcial porque algunas capacidades pedidas no existen todavía.

Fortalezas demostrables

Chroma persistente, embeddings multilingües, reranker real, LangGraph compilado, MCP oficial, JWT staff, fallbacks explícitos y estado de runtime en cada respuesta.

Orquestación

Los pasos reales de LangGraph

  1. validate_inputLimpia la consulta, rechaza vacío y fuerza idioma español.
  2. handle_incidentAntes de RAG, detecta altas, confirmaciones o consultas de incidentes.
  3. retrieve_contextBusca la consulta y suma location_hint cuando existe.
  4. evaluate_contextAcepta evidencia si el primer score es ≥ 0,25; también reconoce consultas operativas sobre salas.
  5. decide_tool_usageDecide si corresponde pedir get_gallery_status a MCP.
  6. execute_toolEjecuta MCP, registra input, salida, estado y latencia.
  7. generate_answer / generate_no_evidenceInvoca Gemini con evidencia o responde que falta contexto sin inventar.
  8. finalizeConstruye el contrato final y termina en END.
Precisión para la entrega: usa LangGraph de verdad, pero no es un agente cíclico. Todas las aristas avanzan hacia END; no hay retorno, replanificación ni segundo intento dentro del grafo.

Orden de relevancia

Ranking y reranking, sin magia

Chroma produce un orden semántico inicial. Después, un cross-encoder analiza cada par consulta–pasaje con más precisión. El score final combina ambos.

25% vector 75% reranker
score final = 0,25 × score vectorial + 0,75 × score reranker

Cómo se calculan los componentes

  • Vectorial: clamp(1 − distancia_coseno / 2).
  • Reranker: sigmoid del logit del cross-encoder.
  • Modelo: cross-encoder/mmarco-mMiniLMv2-L12-H384-v1.
  • Orden: score final descendente.

Ejemplo numérico

Supongamos un fragmento con score vectorial 0,80 y score del reranker 0,60:

0,25 × 0,80 + 0,75 × 0,60

0,20 + 0,45 = 0,65

Score final: 0,65. Supera el umbral 0,25 y puede alimentar a Gemini.

Autorización y operaciones

Visitante, personal e incidentes

Visitante

Chat público
  • Consulta el corpus mediante RAG.
  • Puede pedir el estado operativo de salas mediante MCP.
  • No puede crear ni leer incidentes internos.
  • Aunque envíe user_role: "staff", la API lo fuerza a visitante sin JWT.

Personal

JWT HS256
  • Inicia sesión contra hash bcrypt en SQLite.
  • Puede consultar incidentes por ID mediante chat + MCP.
  • Puede preparar y confirmar altas conversacionales.
  • Puede usar el formulario estructurado para alta directa.

Generación, trazas y degradación

Gemini, LangChain, LangSmith y fallbacks

Gemini

Modelo configurado: gemini-2.5-flash mediante ChatGoogleGenerativeAI, con dos reintentos.

El prompt exige español, evidencia, citas por título y prioridad para datos MCP.

LangChain

Se usa langchain_core.messages y el adaptador de Gemini.

No hay una chain LCEL que coordine retrieval, tools y generación: eso lo hace LangGraph más código Python.

LangSmith

Se habilita si tracing está activo y hay API key. Grafo y Gemini envían run name, tags, rol, idioma y trace ID.

No se verificó entrega externa de trazas durante esta auditoría.

Escalera de fallbacks

  1. Chroma no inicia o falla el warmup → índice léxico JSON.
  2. Falla el reranker → conserva el ranking vectorial.
  3. Falla Gemini o falta la clave → respuesta local basada en fragmentos.
  4. No hay evidencia ≥ 0,25 → mensaje de aclaración sin invocar generación.
  5. Falla MCP → tool call con error y respuesta explícitamente degradada.
Observabilidad incompleta: hay trazas condicionales de LangSmith y latencia por tool, pero no hay Arize ni métricas de throughput, alucinaciones, costos o recursos exigidas por el enunciado.

Ejecución empaquetada

Los tres servicios Docker Compose

1. ui

Streamlit en puerto 8501. Sólo necesita la URL del backend y espera a que FastAPI esté saludable.

2. backend

FastAPI en puerto 8000. Ejecuta ingesta léxica, ingesta Chroma y luego Uvicorn. Monta corpus, índices, SQLite y caché Hugging Face.

3. mcp-server

Servidor MCP streamable HTTP en puerto 8001. Inicializa SQLite y expone las tools operativas.

Alcance real: Docker Compose organiza servicios y healthchecks. No hay manifiestos Kubernetes, funciones serverless ni scripts de escalado.

Camino hacia cumplimiento completo

Brechas priorizadas

1

Convertir el DAG en un ciclo controlado

Agregar evaluación de respuesta y una arista de retorno con máximo de iteraciones. Debe quedar claro cuándo reconsulta, cuándo usa otra tool y cuándo termina.

2

Completar observabilidad

Integrar Arize o justificar una alternativa, medir latencia total, throughput, errores, costo/tokens, calidad factual y recursos; documentar umbrales y alertas.

3

Agregar despliegue de plataforma

Crear manifiestos Kubernetes o una opción serverless, probes, secrets, límites de CPU/memoria, autoscaling y procedimiento de rollback.

4

Alinear la orquestación LangChain

Modelar al menos la preparación de prompt y generación como Runnable/chain observable, o documentar explícitamente por qué LangGraph reemplaza esa función.

5

Endurecer confirmaciones distribuidas

Persistir pendientes y nonces con consumo atómico; decidir si el formulario directo debe exigir confirmación equivalente.

6

Cerrar diferencias entre código y documentación

Conectar o retirar get_accessibility_info, completar el catálogo real, actualizar README/C4 y documentar qué corpus sí se indexa.

Honestidad arquitectónica

Implementación real versus intención

Está realmente conectado

  • Streamlit → FastAPI → LangGraph.
  • Chroma con 13 chunks y fallback léxico.
  • Embeddings y cross-encoder locales.
  • Gemini con fallback local explícito.
  • MCP streamable HTTP sobre SQLite.
  • JWT staff y confirmación conversacional.
  • LangSmith condicional y runtime status.
  • Docker Compose con tres servicios.

Es intención, placeholder o deriva

  • /artworks/{id} no tiene catálogo real.
  • get_accessibility_info existe, pero el agente no puede llamarla.
  • El C4 menciona inventario y tours sin operaciones ejecutables.
  • Una docstring antigua dice que MCP llegará “later”, aunque ya existe cliente/servidor real.
  • README omite get_incident al listar tools.
  • No existen ciclos, Arize, Kubernetes, serverless ni métricas completas.
Cómo presentarlo bien: no digas “cumple todo”. Decí: “La base de producción está implementada y es demostrable; la auditoría identifica con precisión qué falta para satisfacer el enunciado completo”. Eso muestra criterio de ingeniería, no debilidad.

Presentación

Guion oral de 3 minutos

0:00–0:30 · Problema y arquitectura. “Este proyecto es un asistente en español para visitantes y personal del British Museum. La interfaz está en Streamlit, FastAPI valida los contratos y la identidad, y LangGraph decide si recuperar conocimiento, consultar una operación del museo o generar una respuesta.”

0:30–1:10 · RAG y ranking. “El RAG actual indexa 13 fragmentos del corpus español en Chroma. Usa embeddings multilingües y recupera diez candidatos. Después, un cross-encoder los reordena: el score final pesa 25% la similitud vectorial y 75% el reranker. Los cuatro mejores pasan al agente y sólo se consideran evidencia cuando el primero supera 0,25.”

1:10–1:45 · MCP y seguridad. “Para datos cambiantes, como el estado de una sala, el agente usa tools MCP respaldadas por SQLite. El rol staff no se confía al navegador: requiere un JWT válido. Las altas conversacionales de incidentes además necesitan una confirmación con nonce dentro de cinco minutos.”

1:45–2:20 · Gemini y resiliencia. “Gemini 2.5 Flash redacta usando sólo el contexto recuperado y los datos MCP. Si Chroma falla se usa búsqueda léxica; si falla el reranker se conserva el orden vectorial; si falla Gemini se responde con un fallback local. La respuesta siempre informa fuentes, scores, tools y componentes activos.”

2:20–3:00 · Evaluación honesta. “La solución cumple retrieval vectorial, reranking, MCP, documentación arquitectónica y una base de despliegue con tres servicios. No obstante, el LangGraph actual es acíclico, falta Arize y métricas completas, y no hay Kubernetes ni serverless. Por eso la evaluación correcta es cumplimiento parcial, con una hoja de ruta concreta para cerrar esas brechas.”
