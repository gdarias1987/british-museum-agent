La respuesta corta

Sí: la base solicitada quedó implementada y verificada

El sistema ejecuta un RAG en español con ChromaDB, embeddings multilingües, reranking Hugging Face, LangGraph, MCP, Gemini y LangSmith. Phoenix OSS agrega trazas locales; el backend expone métricas y existe una ruta Kubernetes preparada.

Verificado end-to-end

La consulta real respondió con Chroma, reranker, Gemini, LangSmith activo y una traza de proyecto visible en Phoenix local.

Límites honestos

AX Cloud no está configurado, no se incluye Prometheus/Grafana y Kubernetes no fue aplicado contra un cluster real. La calidad factual todavía usa proxies.

Orquestación

Los pasos reales de LangGraph

  1. validate_inputRechaza consultas inválidas y normaliza el idioma.
  2. handle_incidentDetecta altas, confirmaciones o consultas de incidentes antes de RAG.
  3. retrieve_contextBusca en Chroma; incorpora location_hint.
  4. evaluate_contextDecide si hay evidencia suficiente para continuar.
  5. decide_tool_usageDetermina si corresponde consultar una tool MCP.
  6. execute_toolConsulta estado operativo y registra éxito, error y latencia.
  7. generate_answerGenera con Gemini mediante la pipeline LCEL; si no hay evidencia usa respuesta segura.
  8. evaluate_or_refineEvalúa grounding y puede refinar la consulta una sola vez.
  9. finalizeConstruye el contrato final y termina en END.
El ciclo existe, pero está acotado:

La única vuelta posible es evaluate_or_refine → retrieve_context. El estado cuenta intentos y el máximo es dos. Después, todas las rutas pasan por finalize → END. Así se cumple el ciclo sin permitir loops infinitos ni repetir operaciones MCP.

Evidencia: src/british_museum_agent/agent/graph.py y src/british_museum_agent/orchestration/quality.py

Recuperación aumentada

Qué RAG hacemos

Ingesta

  1. Lee el corpus español en Markdown/PDF.
  2. Normaliza y divide en chunks.
  3. Calcula fingerprint del corpus.
  4. Genera embeddings con paraphrase-multilingual-MiniLM-L12-v2.
  5. Persiste la colección british_museum_es en Chroma.

Consulta

  1. Embedding de la pregunta.
  2. Consulta vectorial de candidatos.
  3. Reranking con cross-encoder Hugging Face.
  4. Filtrado por evidencia y armado del contexto.
  5. Gemini responde sólo con ese contexto.
Estado ejecutado: 55 chunks en Chroma, backend chroma y reranker huggingface_cross_encoder activos. Si Chroma falla, existe fallback léxico explícito.

Relevancia

Ranking y re-ranking

Ranking inicial

Chroma ordena candidatos por similitud vectorial. Recupera más documentos que los que finalmente se entregan al modelo.

Re-ranking

El cross-encoder compara pregunta y documento con atención conjunta. El score final combina 25% similitud vectorial + 75% reranker.

El agente entrega los mejores fragmentos al prompt. El primer score debe superar el umbral configurado para considerar que hay evidencia; si no, refina una vez o responde sin inventar.

Organización del código

Estructura del proyecto

Cada componente del pipeline RAG y del agente tiene su propia carpeta, con contratos, tests y documentación. El proyecto sigue una arquitectura hexagonal (puertos y adaptadores).

retrieval/

Conecta con ChromaDB persistente para búsqueda semántica. Incluye embeddings multilingües locales (paraphrase-multilingual-MiniLM-L12-v2), indexación idempotente con fingerprint, carga de corpus desde Markdown/PDF, y un fallback léxico con stemming en español si Chroma no está disponible.

Archivos: vector_store.py, corpus.py, knowledge_base.py, indexer.py

ranking/

Implementa el re-ranker cross-encoder (mmarco-mMiniLMv2-L12-H384-v1). Toma los candidatos de Chroma y los reordena por relevancia real. El score final combina 25% similitud vectorial + 75% reranker. Expone estado de salud (reranker_active) para el endpoint de health check de la API.

Archivos: reranker.py

orchestration/

Orquestación con LangChain: define la evaluación determinista de grounding (evaluate_grounding) que mide evidencia, cobertura de fuentes y longitud de respuesta. También refina la consulta para reintentos (refine_retrieval_query). El pipeline de generación (LCEL) se re-exporta desde aquí para que la carpeta exponga todos los símbolos de orquestación.

Archivos: quality.py, __init__.py (re-exporta AnswerGenerator)

agent/

Agente cíclico con LangGraph. StateGraph de 9 nodos que valida input, maneja incidentes, recupera contexto, evalúa evidencia, decide si usa tools MCP, genera respuesta con Gemini y evalúa si refinar (máximo 2 intentos). Cada nodo tiene una ruta condicional; el ciclo está acotado para evitar loops infinitos. Incluye MemorySaver checkpointer que persiste el estado del grafo entre invocaciones usando thread_id por sesión, permitiendo reanudar ejecución o inspeccionar estados intermedios.

Archivos: graph.py (MemorySaver + StateGraph)

adapters_mcp/

Implementación del Model Context Protocol 1.28.1. Servidor FastMCP con transporte Streamable HTTP y 4 tools: get_gallery_status, get_accessibility_info, create_incident, get_incident. Las tools de escritura están protegidas por un token interno HMAC que viaja como header de transporte (X-MCP-Internal-Token), nunca como argumento de tool. El cliente MCP se comunica con el servidor a través del mismo protocolo, con health check propio.

Archivos: server.py, client.py, museum_tools.py

observability/

Métricas Prometheus in-process (ServiceMetrics) para HTTP (requests, errores, latencia por ruta), chat (confianza, groundedness proxy, hallucination risk proxy, tool errors) y proceso (CPU, memoria). Endpoint /metrics en formato Prometheus y /api/v1/metrics/summary en JSON. Trazabilidad con Arize Phoenix vía OTLP exporter gRPC + OpenInference LangChain instrumentation. LangSmith integrado por environment variables con tags y metadata.

Archivos: metrics.py, tracing.py, quality.py

deploy/

Despliegue con Kustomize: base con namespace, backend, UI, MCP server, Phoenix, PVC (4 volúmenes), HPA (UI 2–5 réplicas, backend 1), NetworkPolicies (6 reglas) y Secret template. Overlay dev reduce réplicas. Scripts de automatización: PowerShell (deploy_k8s.ps1) con validate → render → dry-run → apply → status → rollback, y validador estático Python (validate_k8s.py) de 177 checks sin dependencias externas.

Carpetas: base/, overlays/dev/
Arquitectura hexagonal: Además de las carpetas del enunciado, el proyecto incluye api/ (endpoints FastAPI), application/ (casos de uso), domain/ (modelos de dominio), generation/ (pipeline LLM), infrastructure/ (repositorio SQLite) e interfaces/ (UI Streamlit). Todo está en src/british_museum_agent/.

Generación, trazas y degradación

Gemini, LangChain, LangSmith y Phoenix

Gemini

gemini-2.5-flash genera en español con evidencia y datos MCP. Si falla, hay fallback local explícito.

LangChain

La generación usa LCEL: RunnableLambda → ChatPromptTemplate → modelo → StrOutputParser.

LangSmith

Runtime verificado como activo en el proyecto british-museum-agent; registra runs y metadata técnica.

Phoenix OSS integrado:

Compose levanta Phoenix persistente en 6006. OpenTelemetry/OpenInference envía trazas OTLP con inputs/outputs ocultos. La API de Phoenix verificó el proyecto british-museum-agent.

Ejecución

Docker, persistencia y despliegue

Compose local

docker compose up --build inicia Phoenix, MCP, backend y UI. El backend ingesta/indexa durante el primer arranque; los datos se montan fuera de la imagen.

Puertos: UI 8501, API 8000, MCP 8001, Phoenix 6006.

Kubernetes

deploy/base y deploy/overlays/dev incluyen Kustomize, PVC, probes, NetworkPolicy, HPA y Secret de ejemplo.

La UI escala 2–5. El backend queda en 1 réplica porque SQLite/Chroma usan almacenamiento ReadWriteOnce.

Automatización: scripts/validate_k8s.py valida 177 checks; scripts/deploy_k8s.ps1 soporta validate, render, dry-run, apply, status y rollback. El HPA necesita un metrics server instalado en el cluster.

Validación

Testing: 115 casos de prueba

Cómo ejecutar

pytest -q corre los 115 tests (~11s). La suite se agrupa por módulo:

  • tests/test_agent_graph.py (6) — grafo LangGraph end-to-end
  • tests/test_chat_incident_api.py (17) — API REST + incidentes
  • tests/test_mcp_tools.py (10) — tools MCP + SQLite
  • tests/test_observability.py (62) — métricas, trazas, calidad
  • tests/test_ranking.py (4) — reranker cross-encoder
  • tests/test_retrieval_knowledge_base.py (8) — Chroma + indexación
  • tests/test_security.py (8) — auth, rate-limit, JWT

Casos de uso cubiertos

  • 🔎 Consulta RAG con fuentes — pregunta sobre Egipto, obtiene respuesta citando fragmentos de conocimiento
  • 🏛️ Estado operativo — horarios, galerías cerradas, MCP tool sin evidencia RAG
  • ⚠️ Incidente de sala — flujo completo: confirmación → apertura → nota → cierre
  • ❌ Sin evidencia — pregunta fuera del corpus, el agente deriva a no_evidence
  • 🔁 Checkpoints — verifica que MemorySaver persiste estado entre invocaciones
  • 🛡️ Seguridad — rate-limit, JWT inválido/api-key faltante, CORS, SQLi no ejecutable
  • 📊 Métricas — latencia, hallucination risk proxy, groundedness, recursos, trazas Phoenix
